**Model details:** Each policy is a 32 → 512 → 544 → 208 → 8 multilayer perceptron: 411,000 individually owned trainable parameters. All agent-specific weights together total **4,110,000,000 parameters**, persisted as **8,220,000,000 bytes** (FP16). The models learned a synthetic regression target via PyTorch AdamW. Mean training loss changed **1.3451 → 0.9276**; this is not a real-world benchmark.

**Ability adapters:** 10 million independent 32-dimensional heads, stored in 640 MB plus small status and ledger records. Their targets are synthetic and ID-derived. That training result is not a claim of 10 million independent real tasks, tools, or expert abilities.

## Important limitations

1. **Real AI inference is not connected.** Five brain slots are separate roles, not independent deployed frontier LLMs. The backend supports configured Ollama and cloud model endpoints but the source package installs none.
2. **Hardening remains incomplete.** The observatory binds loopback by default, but public deployment needs TLS, authentication, rate limits, network isolation and secrets governance. Do not expose this host directly to the Internet.
3. **No verified trading performance.** Trading examples are synthetic/read-only. No broker orders, authenticated market-data backtests, risk-qualified paper runs or profit claims.
4. **No externally evaluated general intelligence.** The 1,000 curriculum tracks are catalog definitions. They need real unseen tasks, contamination checks and independent evaluators.
5. **No 10,000 simultaneous model calls.** The workers are 10,000 asyncio mailboxes backed by a capped shared model gateway. The laptop cannot afford 10k concurrent LLM generations.
6. **Checkpoint distribution is separate.** The small v1.0 source ZIP omits the 8.22 GB per-agent model bank, the 640 MB ability bank and adaptive checkpoints. A separate ~7 MB sample ZIP includes 10 trained agent weight rows for an inspectable synthetic-policy demonstration; it is not a fleet replacement. Those were verified in this working environment and can be regenerated on the target laptop using included training scripts. Training is not automatically invoked by extracting the ZIP.
7. **There is no perpetual background execution.** To keep training or monitoring active, the user needs an explicitly configured host and scheduling/restart supervision. This session performs work only while active.

## Run on Windows (explicit local steps)

1. Extract source ZIP and open PowerShell in that folder; verify at least 11 GB free disk beyond the OS and local model downloads.
2. Install Python/PyTorch as reviewed: `python -m pip install -r training/requirements.txt`.
3. Execute **full** neural-policy learning: `.\training\train_full_10000_windows.ps1`. It resumes verified rows and stops on corrupted checkpoints; it does not automatically run continuously.
4. If desired, initialize the separate ten-million synthetic adapter bank: `.\training\train_all_abilities_windows.ps1` (requires additional disk space).
5. Audit locally: `.\training\verify_local_training_windows.ps1`.
6. Connect an approved local model endpoint before invoking five-brain language-model missions. No provider keys should ever be committed to GitHub.
7. Start UI: `python server.py` and open `http://127.0.0.1:8788` on the same computer.
